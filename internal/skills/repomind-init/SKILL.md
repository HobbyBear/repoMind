# RepoMind 初始化

## 目标

建立一个轻量、可读、可直接由 Agent 维护的 `.repomind`：

```text
.repomind/
├── concepts/
├── modules/
└── troubles/
```

人工 Markdown 是唯一业务事实来源。初始化只生成高置信业务概念和模块知识，不为凑数量创建卡片，也不从代码猜测故障经验。

## 步骤 1：确认范围与安全边界

- 只创建或更新 `.repomind/concepts/**/*.md` 和 `.repomind/modules/**/*.md`。
- 保留并合并已有人工文档，不整库覆盖。
- 不修改业务代码，不提交、不推送。
- 不读取或依赖生成目录、缓存索引和外部图谱。
- 已有 `troubles` 原样保留；只有用户提供了可复用排查经验时才新增或更新。

## 步骤 2：读取现有知识

使用平台原生文件搜索和读取：

1. 列出 `.repomind/concepts/**/*.md`、`.repomind/modules/**/*.md`、`.repomind/troubles/**/*.md`。
2. 先读取 frontmatter 和标题，了解已有所有者和命名。
3. 仅在需要合并时打开对应正文。
4. 记录重复名称、缺失元数据、明显过时入口和已有人工约束。

已有人工结论优先保留；当前代码明确冲突时标记冲突，不静默覆盖。

## 步骤 3：分析仓库

按批次读取以下高信号材料：

- 根 README、产品说明和架构文档。
- 应用入口、路由、服务接口、领域模型和核心配置。
- 稳定包名、公开类型、方法和接口。
- 测试中反复出现的业务词和边界条件。

只读最小必要片段。目录名或技术名词本身不能直接视为业务概念。

## 步骤 4：筛选候选

### 业务概念

只有满足以下至少两项才创建：

- 在接口、服务、模型、配置或用户侧文案中反复出现。
- 有稳定规则、生命周期、状态或业务边界。
- 容易与相邻概念混淆，值得单独解释。
- 用户后续很可能直接用该名称提问。

### 业务模块

只有满足以下条件才创建：

- 承担明确业务职责，而不是普通工具目录。
- 有稳定入口或跨模块约束。
- 文档能帮助后续定位修改入口、影响面或风险。

技术支撑模块只有承载业务入口或关键跨模块约束时才建卡片。

## 步骤 5：选择动作

对每个候选执行：

- `SKIP`：现有文档已完整覆盖。
- `UPDATE`：现有文档对象相同，但描述、入口或边界过时。
- `MERGE`：多个文档属于同一唯一所有者，应合并去重。
- `CREATE`：没有同一对象的文档，且证据足够。
- `DISCARD`：低置信技术名词、字段名、临时能力或无法说明业务价值的候选。

默认优先更新和合并，不因关键词相同就合并不同对象。

## 步骤 6：写入固定结构

### concept

```markdown
---
name: "概念名"
description: "它是什么、何时会被提及以及核心边界。"
status: active
keywords: []
code_refs: []
---

# 概念名

## 是什么

## 核心规则

## 适用场景与边界

## 关联知识
```

概念正文不写 SQL、长调用链和函数内部步骤。

### module

```markdown
---
name: "模块名"
description: "模块承担什么业务、何时打开以及典型影响面。"
status: active
keywords: []
code_refs: []
---

# 模块名

## 模块职责

## 包含能力

## 技术入口

## 关键约束

## 关联知识
```

技术入口写稳定函数、方法、类型或接口及其用途，不写行号和长调用链。

## 步骤 7：压缩与自检

每篇新建或更新文档都必须直接自检：

- `name/description/status` 完整；`description` 不超过 120 个字符。
- `keywords` 为 3-8 个高判别词，单个不超过 32 个字符。
- `code_refs` 去重，只保存稳定入口。
- 必备章节有实际内容，没有“待补充”占位。
- 文件超过 8 KiB 时继续精简；超过 12 KiB 必须按独立主题拆分。
- 单章节超过 2 KiB 时继续精简；超过 4 KiB 必须拆分。
- 没有重复规则、修订记录、调查过程和代码可直接看出的普通事实。

## 步骤 8：输出初始化摘要

说明：

- 新建、更新、合并和丢弃了哪些候选。
- 每篇文档的证据来源和稳定入口。
- 哪些候选证据不足而未创建。
- 哪些已有文档存在冲突或待人工确认。
- 是否建议继续执行 `repomind-prd` 导入需求文档中的业务语义。
